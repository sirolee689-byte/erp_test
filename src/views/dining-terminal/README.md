# 饭堂刷卡终端

## 入口与用途

- 页面入口：`/dining-terminal`。
- 页面供饭堂刷卡电脑使用，不要求员工或管理员账号登录。
- 服务端按请求IP匹配目标饭堂库的 `UB_ERP_Dining_machine`；IP未登记时页面只显示未授权提示。

## 业务规则

- 所有已授权窗口通用，不按部门或 `jw` 限制。
- 饭卡号固定10位，同时匹配员工档案的 `card_number/new_card_number`；员工必须 `del=0/pass=1`。
- 仅处理午餐和晚餐。正常模式按配置 `two1/two2、three1/three2` 自动识别当前餐别。
- 只认 `UB_ERP_Dining_meal` 中 `del=0/pass=1` 的报餐；旧系统同餐多条菜式记录合并为一次报餐资格。
- `closed=0` 时未报餐拒绝刷卡，`closed=1` 时允许补餐；成功流水写入 `UB_ERP_Dining_meal_log`。
- 同一员工、日期、餐别跨窗口只允许一次成功刷卡，服务端使用事务级业务锁处理并发。

## 测试与正式模式

- `DINING_TERMINAL_TEST_MODE=true` 仅在 `DINING_DB_DATABASE=UB_ERP_V2.0` 时生效，可手动选择日期和午/晚餐。
- 目标库切换为 `ERP_UB` 后，后端强制关闭手动模式，即使环境变量仍为 `true` 也不放行。
- 测试库产生的报餐和刷卡流水不得迁移到正式库。

## 页面操作

- 顶部操作栏在测试模式下依次显示日期、午/晚餐、饭卡输入框和“自动刷卡”；正式模式隐藏测试条件。
- 读卡器把饭卡号输入焦点中的输入框并发送回车，页面提交刷卡；“自动刷卡”按钮作为手工提交入口，不按输入位数提前提交。
- 当前测试期模拟实际刷卡机行为：输入框失焦后会自动抢回焦点；测试日期暂时固定为 `2026-07-31`，只允许切换午餐/晚餐。
- 结果通过短暂的顶部大字浮层、颜色和语音反馈，不长期占用列表空间。
- 页面紧凑显示应刷、已刷、未刷、补刷人数。人数按日期和餐别覆盖全部窗口，并按员工去重；列表只显示当前窗口的成功刷卡流水。
- 列表只保留刷卡时间、员工姓名和状态，支持每页10、20、50条，默认10条；成功刷卡及切换测试条件后返回第一页。
- 下方按70%/30%分为两个卡片：左侧是当前窗口刷卡流水，右侧是全部窗口未刷卡人员名单；名单按报餐员工 `uid` 去重并可滚动查看。
- 语音文件位于 `public/dining-audio/`，沿用旧饭堂系统的提示音。

## 分页接口

- `GET /api/dining-terminal/recent` 接受 `page/pageSize`，其中 `pageSize` 只允许10、20、50。
- 返回 `rows/pagination/summary`；SQL Server 2008 R2 使用 `ROW_NUMBER()` 分页，并先筛选当前窗口流水再复用临时结果统计总条数，避免列表和总数重复扫描流水表。
