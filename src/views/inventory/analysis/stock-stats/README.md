## 查询超时规则

| 场景 | 前端超时 | 进度提示 |
|------|----------|----------|
| 默认全仓或选了物料类别 | 120 秒 | 转动图标 + 滑动进度条 + 0.1 秒刷新等待时间 + 阶段文案轮换；超过 6 秒提示「界面未卡死」 |

统计进行中会禁用弹窗关闭与「取消」按钮，避免重复提交。

## 主表口径

- 基础行由入库和出库两侧并集生成：`UB_ERP_Stocks_Storage / UB_ERP_Stocks_Storage_list` 与 `UB_ERP_Stocks_out / UB_ERP_Stocks_out_list` 均按 `kcaa01 + 仓库编码 + 仓库名称` 分组后合并。
- 展示字段再按物料编码反查 `UB_ERP_Bom_000` 最新有效记录补齐。
- 类别名称通过 `UB_ERP_Stocks_material.code = kcaa05` 关联。
- 颜色名称通过 `UB_ERP_Stocks_colorcode.code = kcaa11` 关联。
- `实存数量`、`可用数量` 均按 `帐存数量 - 未审核出库数量`。
- `入库未审数量` 按旧系统兼容口径只判断主表 `pass=0`，暂不额外补 `del=0`。
- `在途数量`（2026-07-02）：按旧系统口径批量计算，不参与帐存/实存/可用。采购侧汇总 `UB_ERP_Buy_order` + `UB_ERP_Buy_order_list`（主表 `del=0/pass=1`、采购日期 `>=2019-01-01` 且 `< 库存截止日期`），明细 `kcaa01` 匹配物料，`kcak03` 经 `kcaa26/kcaa27` 换算；采购入库侧汇总 `UB_ERP_Stocks_Storage` + `UB_ERP_Stocks_Storage_list`（主表 `del=0/pass=1/kcan03=1`、`kcan04=采购单号`、`kcan06=当前仓库`、入库日期 `< 库存截止日期`），`kcao03` 同样换算；在途 = `max(0, 采购换算合计 - 采购入库换算合计)`；`kcaa27=1` 且 `kcaa26` 无效时按 0 处理。

## 性能记录

- 2026-07-03 阶段2：`/api/stock-stats/report` 后端 SQL 从单条大型 CTE 改为会话临时表分段汇总。先落 `#base/#ai/#ui/#oa/#bom/#pp/#pi`，再做最终关联和筛选，避免 SQL Server 2008 R2 对全仓库存统计生成慢执行计划。
- 本次不改变业务口径：基础行仍按当前实现的入库/出库并集生成；`入库未审数量` 继续按旧系统兼容口径只判断主表 `pass=0`；`实存数量` 和 `可用数量` 仍为 `帐存数量 - 未审核出库数量`；`在途数量` 只展示，不参与帐存/实存/可用。
- 以 `库存截止日期=2026-07-03、仓库=001 货仓、只统计物料=是、库存不等于零=是` 的全仓条件实测：旧大型 CTE 完整返回超过 30 秒中止；临时表分段方案返回 4666 行约 6.7 秒。
